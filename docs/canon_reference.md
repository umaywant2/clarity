## **1. Purpose of the Canon**

The TriadicFrameworks Canon defines the structural, mathematical, and semantic foundations of the RTT Suite.  
It ensures:

- **consistency** across modules  
- **lineage integrity** across evaluators  
- **semantic stability** across the SI Ontology  
- **predictable behavior** across engines and pipelines  

The canon is the *single source of truth* for:

- triadic structure  
- substrate primitives  
- evaluator lineage  
- analyzer layers  
- module metadata  
- semantic API behavior

## **3. Triadic Structure**

TriadicFrameworks is built on the **S‑R‑A triad**:

### **Structure (S)**  
Form, constraint, axis, stability.

### **Resonance (R)**  
Relation, harmonic, field, coherence.

### **Activation (A)**  
Impulse, motion, surge, volatility.

Every evaluator, module, and semantic entity maps to one or more triadic layers.

## **5. Evaluator Lineage**

All RTT evaluators follow the same lineage:

```
qmroot → triad → layer → operator → evaluator
```

### **Evaluator Pipeline**
1. **Drift** — ΔS / ΔR / ΔA extraction  
2. **Coherence** — variance + harmonic envelope  
3. **Regime** — triadic dominance  
4. **Clarity** — pulse + spectral primitives  

The **Session Interpreter** runs all four sequentially.

## **6. Analyzer Layers**

The canon defines six analyzer layers:

| Layer | Purpose |
|-------|---------|
| **Operator Layer** | spectral, drift, regime, primitive operators |
| **Dimensional Layer** | D0–D7 dimensional families |
| **Drift Layer** | drift families + velocity mapping |
| **Coherence Layer** | envelope + variance + stability |
| **Regime Layer** | dominance + stability |
| **Crosscut Layer** | lineage, envelope, stability, compatibility |

Each module declares its layer participation via `module.json`.
